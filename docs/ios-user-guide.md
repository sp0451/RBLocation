# CLocation iOS 使用说明

适用版本：CLocation M0 / 0.1.0。更新日期：2026-10-21。首测设备：iPhone 16 Pro / iOS 27.0.1。

## 先选择使用方式

| 方式 | 操作入口 | 当前验证情况 |
| --- | --- | --- |
| 手机端 CLocation | 本机配对 + LocalDevVPN，然后在 App 内连接、设置和停止 | 用户反馈安装 LocalDevVPN 后测试成功；具体场景尚未逐项记录 |
| Mac 辅助 | iPhone 通过 USB 连接 Mac，由开发工具设置和清除 | 已通过上海 → 北京 → 清除恢复测试，苹果地图与微信 8.0.79 位置页生效 |

手机端按下方顺序准备；Mac 方式见本文“Mac 辅助操作”。两种方式分开使用，避免同时设置位置，导致无法判断谁修改或清除了定位。手机端结果来源见 [用户测试反馈](validation/2026-10-21-ios-user-feedback.md)。

当前 App 支持手输 WGS84 经纬度、上海/北京/深圳示例点，以及连接、设置和停止。地图选点、地名搜索、路线和摇杆尚未接入。

## 手机端首次准备

### 1. 安装并启动 CLocation

CLocation 当前通过开发签名安装，尚无面向用户发布的 App Store 安装版本。已经装好并能打开的用户可以跳到下一步。

开发者在 Mac 的项目根目录执行：

```sh
flutter pub get
flutter devices
```

复制目标 iPhone 的设备标识，再执行；先将示例字符串替换为自己的标识：

```sh
IOS_DEVICE_ID='替换为你的iPhone设备标识'
flutter run --debug -d "$IOS_DEVICE_ID"
```

使用自己的有效开发签名。在 Xcode 的 Runner → Signing & Capabilities 中选择可用 Team；首次连接时解锁 iPhone，并按系统提示信任这台 Mac、完成 Xcode 设备准备。

目前真机启动验证使用的是 Debug 包。测试时优先通过 `flutter run` 或 Xcode 启动；如果退出调试后点击图标无法启动，先重新从开发工具运行，不能把 Debug 启动限制判断为定位服务故障。独立安装的 Release 包仍需另行构建与验证。

### 2. 开启开发者模式

打开 iPhone：**设置 → 隐私与安全性 → 开发者模式**，开启后按系统提示重启并确认。已开启则无需重复操作。

如果没有该入口，先连接 Xcode 并完成开发设备识别，或安装开发签名应用，再检查系统设置。入口和确认方式以手机实际提示为准。[Apple 开发者模式说明](https://developer.apple.com/documentation/xcode/enabling-developer-mode-on-a-device)、[Apple 开发者模式介绍](https://developer.apple.com/videos/play/wwdc2022/110344/)

### 3. 授予 App 权限

首次打开 CLocation 时，按用途处理权限：

| 权限 | 如何选择 | 用途 |
| --- | --- | --- |
| 本地网络 | 允许 | 发现本机配对服务及使用本地设备服务链路 |
| 定位 | 使用 App 时允许，并保留精确位置 | 读取定位样本，检查模拟效果和停止后的恢复 |
| 无线数据 | 首测至少允许无线局域网 | 使用本地网络；本轮以 Wi-Fi 验证 |
| 通知 | 建议允许 | 切换到系统设置配对时，可查看临时验证码通知 |

在首页点击右上角的设置图标进入“设备准备”，可通过“申请定位权限”触发定位授权。已经拒绝过的权限，应到系统中 CLocation 的应用权限页检查。

允许定位只解决观测权限，不代表已经能修改系统位置。通知不是定位引擎；拒绝通知后仍需能及时从 App 查看配对码。

### 4. 安装并连接 LocalDevVPN

从 [LocalDevVPN 官方 App Store 页面](https://apps.apple.com/us/app/localdevvpn/id6755608044) 安装，核对名称为 **LocalDevVPN**、开发者为 **Coxson Engineering LLC**。商店地区是否可下载以实际页面为准。

1. 打开 LocalDevVPN。
2. 如系统询问添加 VPN 配置，按提示确认。
3. 使用其连接功能建立本地隧道。
4. 首测连接 Wi-Fi，保持隧道连接，再回到 CLocation。

该工具提供本地网络隧道，本身不负责修改 GPS。当前 CLocation 使用固定本地目标 `10.7.0.1:49152`；先保留 LocalDevVPN 默认配置，不自行更改隧道地址。普通代理、加速器或其他 VPN 不能据此视为等价替代。已有 VPN 的共存情况尚未验证；遇到冲突时先确认当前实际启用的是哪个配置。[LocalDevVPN 产品说明](https://apps.apple.com/us/app/localdevvpn/id6755608044)

VPN 显示“已连接”只证明隧道已开启，仍要由 CLocation 实际握手确认设备服务是否可用。

### 5. 完成本机六位码配对

以下是当前 App 的 iOS 27 配对流程，依据实现与上游使用说明编写。用户已反馈手机端测试成功，配对中的取消、超时等异常分支仍需分别验证。[上游配对流程参考](https://github.com/ChrisMack32/Locus/blob/main/SETUP.md)

1. 打开 CLocation → 右上角设置图标 → **设备准备**。
2. 点击 **开始设备配对**，按提示允许本地网络和通知。
3. 保留 CLocation 运行，切换至 **设置 → 隐私与安全性 → 开发者模式 → Pair with Host**。
4. 在列表中选择 **CLocation**，发起配对。
5. 如系统先要求锁屏密码，在系统界面输入 iPhone 的锁屏密码。
6. 当系统要求配对验证码时，输入 CLocation 显示的六位临时码；允许通知时也可从当前配对通知查看。
7. 返回 CLocation，等待原生配对完成，再点击 **重新检查准备情况**。

**输入方向：CLocation 显示验证码 → 将验证码输入 iOS 系统配对框。** 锁屏密码与六位配对码是两种不同的输入。不要把锁屏密码输入 App。

配对最长等待约 180 秒；切换到设置后，系统给予 App 的后台时间可能更短。若列表找不到 CLocation、验证码过期或 App 提示取消，回到 App 取消本次配对，重新开始，并及时完成系统操作。已结束尝试的旧验证码不能用于新尝试。

“已完成，继续”按钮不能代替系统配对或强制标记成功。以 App 显示“本机配对”已满足为准；该状态只表示已保存配对记录，设备密钥仍需在连接时验证。Mac 已信任 iPhone，也不等于 CLocation 已完成本机配对。

### 6. 检查准备状态并连接

设备准备页各项含义如下：

| 检查项 | 如何理解 |
| --- | --- |
| 原生定位引擎 | “已接入”说明当前构建包含引擎；不代表协议或定位效果已验证 |
| 本机配对 | “待完成”时先完成六位码配对；“已满足”表示存在受保护的配对记录 |
| 开发者模式与设备准备 | 连接前可能显示“待验证”；实际握手成功后才显示已满足 |
| LocalDevVPN | 连接前可能显示“待验证”；实际隧道握手成功后才显示已满足 |
| 本 App 定位观测 | 表示观测权限状态，不保证已经收到新鲜定位样本 |

完成手动准备后点击 **重新检查准备情况**，返回工作区，点击 **连接设备**。不要等待所有“待验证”项目在连接前自动变绿。

“打开开发者设置”和“检查外部隧道”目前可能只提示手动处理，不能保证跳转到系统对应页面或自动打开 LocalDevVPN；请按上述路径操作。

## 设置模拟位置

1. 确认 LocalDevVPN 连接正常，并在 CLocation 点击“连接设备”。
2. 等待“设备连接”显示 **已连接**。
3. 点击上海、北京或深圳，或手输纬度与经度。
4. 点击 **设置位置**。
5. 查看命令结果，再切换苹果地图，点击定位箭头，观察“我的位置”蓝点。

| 示例点 | 纬度 | 经度 |
| --- | --- | --- |
| 上海 | `31.2304` | `121.4737` |
| 北京 | `39.9042` | `116.4074` |
| 深圳 | `22.5431` | `114.0579` |

坐标使用 WGS84。纬度范围为 −90～90，经度范围为 −180～180。点击示例点只填写输入框，必须点击“设置位置”才会提交。

“设置位置”变灰通常表示尚未连接或仍在处理操作；“连接设备”变灰时先检查本机配对是否待完成，以及是否有配对/停止等操作仍在进行。

### 在微信中确认

进入微信聊天的“＋ → 位置”，打开位置选择页；如出现操作菜单，再选择“发送位置”进入选择页。只检查位置时，无需点击右上角绿色“发送”。

查看地图蓝点、位置标记和附近地点列表。如果仍显示旧城市，点击 **我的位置**；必要时取消并重新打开位置页。地图中心可以被手动拖动，因此只看地图画面移动不足以证明定位生效。

本项目逐项记录的微信结果来自 Mac 辅助方式；手机端另有用户测试成功反馈，但未逐项注明目标 App。实时位置共享、小程序和其他位置功能需要分别测试。

## 停止与恢复真实定位

1. 保持设备服务可连接；手机端使用时先保留 LocalDevVPN。
2. 回到 CLocation，点击 **停止模拟**。
3. 等待清除操作结果，保持 App 前台以获取新的定位样本。
4. 打开苹果地图，点击定位箭头，确认蓝点回到实际区域。
5. 微信如保留旧位置，取消并重新进入位置页，或点击“我的位置”。

完成恢复检查后再结束隧道。强退 CLocation、断开 VPN、拔掉数据线或看到“未连接”，都不能替代清除和恢复确认。

黄色 **需要确认定位恢复** 表示 App 尚未取得自身所需的恢复证据。当前实现启动时也会保留这一要求，因此黄色提示本身不证明设备仍处于模拟位置。它也不能仅因地图显示正常就自动消失。

若清除失败，先恢复隧道/连接条件再重试；若仍无法连接且手边有已准备好的 Mac，可使用下方 Mac 清除命令，然后分别检查地图与微信。不要将错误提示消失当作恢复证据。

## 状态与常见问题

### 状态怎么判断

| 界面信息 | 代表什么 | 接下来做什么 |
| --- | --- | --- |
| 已连接 | 设备服务连接建立 | 主动提交坐标 |
| 已发送（无服务确认） | 定位命令已发出，当前底层没有该命令的服务确认 | 检查新定位样本及独立 App |
| 服务已确认 | 对应操作取得确认，例如连接或配对完成 | 仍需分别验证定位效果 |
| 连接已中断 | 当前设备服务不可用 | 检查隧道后重连；重连不会自动重发旧坐标 |
| 需要确认定位恢复 | 恢复证据尚未闭合 | 检查清除结果及后续真实定位 |

### “设备服务操作失败（原生错误码 1）”

在本项目固定的 idevice 版本中，`1` 对应 Socket I/O 错误：底层通信失败。这个数字本身无法区分隧道未开启、连接被关闭或具体读写失败阶段，也不是坐标格式错误。

建议按以下顺序排查：

1. 确认已安装并打开 **LocalDevVPN**，实际启用其隧道，保留默认配置。
2. 确认首测使用 Wi-Fi，并允许 CLocation 使用本地网络和无线局域网数据。
3. 查看设备准备页“本机配对”是否已满足；缺少配对时重新完成系统流程。
4. 确认开发者模式已开启、Xcode 已完成设备准备。
5. 回到 App 刷新检查，重试“连接设备”；连接成功后再提交位置。

点击“停止模拟”时也可能出现此错误，因为当前实现会在没有连接时尝试重新建立设备服务，再发送清除命令。没有连通服务就无法保证 App 已发出清除。

### 其他常见情况

| 现象 | 处理方式 |
| --- | --- |
| 配对列表看不到 CLocation | 确认 App 正在配对、允许本地网络；回 App 取消后重新开始，及时切换系统设置 |
| 配对突然取消或验证码失效 | 使用新尝试的验证码；系统后台时间可能提前结束配对 |
| 已保存配对记录但连接失败 | 保存记录不等于认证通过；先检查隧道与设备准备，再检查配对是否需要重做 |
| “待验证”刷新后仍不变 | 有些条件只能靠实际握手确认；完成手动准备后尝试连接 |
| 设置后微信仍显示旧点 | 点击“我的位置”或重新进入选择页；仍不变则记录为该目标未通过 |
| 地图正常但 App 黄色条仍在 | 地图观察与 App 自身恢复确认是不同证据，保留提示直到满足 App 的确认条件 |
| 关闭 App 后效果不确定 | 重新打开不会自动重放坐标；先确认当前定位，再连接并清除 |
| 想锁屏、长时间后台或切换蜂窝网络 | 当前未完成这些场景验收，不保证持续可用 |

## Mac 辅助操作：已通过真机验证

这一路径不使用 CLocation 手机端的 LocalDevVPN 和本机六位码配对；需要 Mac/Xcode 与 iPhone 已完成开发连接。它不能证明手机端链路已可用。

### 1. 连接并识别 iPhone

用 USB 连接并解锁 iPhone，完成“信任此电脑”和 Xcode 设备准备。Mac 终端执行：

```sh
xcrun devicectl list devices
```

找到处于 connected 状态的目标 iPhone，复制标识：

```sh
IOS_DEVICE_ID='替换为你的iPhone设备标识'
```

不要将占位文字原样作为设备标识。以下命令使用同一个终端中的变量。

### 2. 设置位置并观察

设置上海：

```sh
xcrun devicectl device simulate location coordinate \
  --device "$IOS_DEVICE_ID" --latitude 31.2304 --longitude 121.4737 --timeout 30
```

设置北京：

```sh
xcrun devicectl device simulate location coordinate \
  --device "$IOS_DEVICE_ID" --latitude 39.9042 --longitude 116.4074 --timeout 30
```

每次设置后，按前文的方法检查地图和微信。CLI 输出 `Set location to: ...` 是命令结果，页面实际变化是另一项证据。

### 3. 必须清除并观察恢复

```sh
xcrun devicectl device simulate location clear \
  --device "$IOS_DEVICE_ID" --timeout 30
```

命令返回 `Cleared location simulation` 后，点击地图定位箭头，并重新打开微信位置页，确认恢复。本机工具帮助提示模拟会持续到清除；关闭终端或拔线不能作为清除方法。

本轮已通过的测试点：上海 → 北京 → 清除恢复；设备和微信版本见 [iPhone 真机测试记录](validation/2026-10-21-ios-mac-location.md)。本说明的命令已按本机 Xcode 27 CLI 和记录核对，其他 Xcode 版本先用 `xcrun devicectl device simulate location --help` 检查是否提供该入口。

## 每次使用的简明顺序

手机端：**Wi-Fi → LocalDevVPN → 打开 CLocation → 检查配对 → 连接设备 → 选点并设置 → 独立观察 → 停止模拟 → 确认恢复**。已有用户测试成功反馈，A/B 与恢复等细分场景按后续记录补充。

Mac 辅助：**USB 连接 → 确认设备 → 设置坐标 → 地图/微信观察 → clear → 确认恢复**。该路径已在本次设备组合通过。

反馈问题时提供系统/App/LocalDevVPN 版本、采用的方式、失败步骤及错误文字即可。截图遮挡真实精确位置、联系人、聊天内容和设备标识，不发送配对文件、锁屏密码或临时验证码。
